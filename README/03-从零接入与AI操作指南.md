# 从零接入与 AI 操作指南

目标是在另一位使用者的 Mac 和 iPhone 上，从本仓库源码完成构建、个人签名、真机安装、配对和 Photoshop 实时预览。所有路径均以该使用者实际克隆的项目根目录为准。

## 先明确使用者需要什么

先阅读 [三者职责](01-三者职责与数据流.md)。只看已保存 PSD 时，完成 Mac、手机和局域网连接即可；需要 Photoshop 未保存修改时，再接入插件。

本项目没有自己的注册系统。Apple 账号用于 Xcode 签名，Adobe 账号用于安装和使用 Adobe 软件，两者均由使用者本人登录。不要索取或记录密码、验证码、私钥，也不要复用作者的账号、开发团队、证书或签名产物。

## 阶段一：确认环境

| 项目 | 要求或说明 |
| --- | --- |
| Mac | 应用最低 macOS 14；构建所用 Xcode 还需满足它自己的 macOS 要求 |
| Xcode | 完整 Xcode，包含对应 SDK；版本需支持使用者的 iPhone 系统版本，Command Line Tools 单独安装不够 |
| Python | Python 3；工程生成器仅使用标准库 |
| iPhone | 应用最低 iOS 17；可解锁、信任此 Mac，并按系统要求启用开发者模式 |
| Apple 账号 | 使用者自己的 Apple Account；个人团队或有权使用的开发团队 |
| Photoshop | 需要实时模式时安装 Photoshop 25.0 / 2024 或以上 |
| Adobe 工具 | 需要实时模式时准备官方 UXP Developer Tool，按 Adobe 当前支持的安装渠道获取 |
| 网络 | Mac 和手机之间可达的局域网；单纯 Wi-Fi 名称相同不保证设备可互通 |

已验证的开发环境包含 Apple Silicon Mac、Xcode 26.3、Photoshop 25.2 和 iPhone 真机。其他组合需要实际构建验证，不能把作者机器上的成功当成当前机器已经成功。

可先运行只读检查：

```sh
xcodebuild -version
xcode-select -p
python3 --version
xcrun devicectl list devices
```

如果 Xcode 指向错误，由使用者切换到已安装的完整 Xcode。首次启动 Xcode 的系统安装、协议、账号与权限提示按实际界面处理，不要仅凭文件存在就判断环境就绪。

## 阶段二：配置使用者自己的签名

仓库公开配置在 `Config/Signing.xcconfig`，不含个人团队。生成的 Xcode 工程会读取它，它又可选加载被 Git 忽略的 `Config/Signing.local.xcconfig`。

1. 在 Xcode → Settings → Accounts 登录使用者自己的 Apple Account，由本人完成密码和验证码输入。
2. 确认有权使用的 Team；没有付费开发计划时，Xcode 可提供 Personal Team。
3. 复制模板，不要覆盖已经存在的个人配置：

   ```sh
   cp -n Config/Signing.local.xcconfig.example Config/Signing.local.xcconfig
   ```

4. 编辑 `Config/Signing.local.xcconfig`，填写实际 Team ID 和自己选择的应用标识符。例如：

   ```xcconfig
   DEVELOPMENT_TEAM = YOUR_TEAM_ID
   PSDMIRROR_IOS_BUNDLE_ID = com.yourname.psdmirror
   PSDMIRROR_MAC_BUNDLE_ID = com.yourname.psdmirror.mac
   ```

   上述内容是占位示例。使用者应替换 Team ID 与 `yourname`，采用该团队可注册的唯一 Bundle ID。Team ID 不是 Apple 邮箱，也不是证书显示名称末尾的个人标识。Bundle ID 本身不是密码，仍需按当前团队的注册情况设置。

5. 运行 `python3 Scripts/generate_project.py`，打开 `PSDMirror.xcodeproj`，选择 `PSDMirror` target，核对 Signing & Capabilities 中的自动签名、Team 和 Bundle Identifier。

签名配置优先写入本地 xcconfig。生成器会覆盖 `project.pbxproj`、共享 schemes 和两个 Info.plist；不要仅依赖 Xcode 工程里的临时手改。它不会重写本地 xcconfig。

Mac target 默认采用本机 ad-hoc 签名，无需 Apple 开发团队；iPhone 真机安装需要使用者的开发签名。不要把作者构建的 `.app`、描述文件或导出的证书当成别人可直接使用的安装方案。

## 阶段三：构建 Mac 应用

在项目根目录执行：

```sh
zsh Scripts/build.sh mac
```

产物为 `build/Mac/Build/Products/Debug/PSDMirrorMac.app`。从 Finder 启动该应用，或之后使用根目录的 `启动Mac端.command`。

验收：窗口显示可扫描的连接二维码和插件连接状态；服务处于运行状态。二维码内自动携带地址和当次配对凭据，界面不要求使用者读取或填写这些字段。允许所需的本地网络通信，按系统实际提示处理防火墙。不要直接关闭整机防火墙。

插件通过本机接口自动连接，固定回环地址为 `127.0.0.1:48766`，与克隆目录无关。不要创建连接文件夹、要求用户选择目录，或写死作者电脑的绝对路径。该接口仅监听本机，不向局域网开放。

## 阶段四：构建并安装手机应用

1. 用数据线连接使用者自己的 iPhone，解锁并信任 Mac；按设备要求启用开发者模式。首次准备或安装期间暂时结束 iPhone 镜像，避免实体手机锁定妨碍调试准备。
2. 在 Xcode 选择 `PSDMirror` scheme、实际 iPhone 作为运行目标，运行构建安装。出现签名错误时检查当前账号会话、Team、Bundle ID 和设备状态。
3. 也可先命令行构建：

   ```sh
   zsh Scripts/build.sh ios
   ```

   构建脚本的 iOS 模式允许 Xcode 更新描述文件和注册设备；执行前应确认这是使用者授权的团队和设备。

4. 如需命令行安装，先读取本机设备列表，再使用当前设备标识和本地配置里的 Bundle ID：

   ```sh
   DEVICE_ID='替换为本机检测到的设备标识'
   IOS_BUNDLE_ID='替换为本地配置中的iOS应用标识'
   xcrun devicectl device install app --device "$DEVICE_ID" build/Device/Build/Products/Debug-iphoneos/PSDMirror.app
   xcrun devicectl device process launch --device "$DEVICE_ID" "$IOS_BUNDLE_ID"
   ```

5. 如果 iOS 要求信任开发者，在手机「设置 → 通用 → VPN 与设备管理」信任使用者本人的开发者身份，然后打开应用；按提示允许本地网络。

验收必须是实体手机能打开 PSD Mirror。只有 `BUILD SUCCEEDED` 或安装命令成功，不等于首次信任和启动已经完成。

免费 Personal Team 的设备描述文件通常在签发后 7 天到期，需要重新构建安装；账号限制和当前规则以 [Apple 开发者账号说明](https://developer.apple.com/help/account/basics/about-your-developer-account) 为准。不要把作者某次签名的到期日期写成所有人的固定到期日。模拟器模式可用 `zsh Scripts/build.sh simulator`，但不能替代实体手机和真实局域网验证。

## 阶段五：先验证已保存 PSD 的预览

1. 在 Mac 添加使用者指定的测试 PSD。
2. 在手机 PSD Mirror 内点「扫码连接」，允许相机权限，扫描正在运行的 Mac 应用显示的二维码。不要改为系统相机扫描，也不要添加手动连接表单。
3. 识别后应用自动连接并显示 PSD 列表。点选测试 PSD，确认手机进入全屏并显示画面；Mac 重启后要扫描新的二维码。
4. 检查适应、铺满、缩放和横竖屏；留白可能来自图片长宽比，不代表退出了全屏。

无法扫码时检查相机权限、Mac 二维码是否完整可见、手机是否为有后置相机的实体设备。扫码后连接失败时检查本地网络权限、服务状态、二维码是否在 Mac 重启后更新，以及网络是否隔离客户端。应用会自动尝试二维码中的多个接口地址；当前协议携带 IPv4 地址。不要复用作者的连接码或手机标识。

## 阶段六：接入 Photoshop 实时模式

1. 使用者安装并启动 Adobe 官方 UXP Developer Tool，按其要求启用开发模式。
2. 在 Photoshop 的首选项/设置 → 增效工具中启用开发人员模式，并按需要重启 Photoshop。此类开关会允许加载本地开发插件，应让使用者明确了解并按当前操作权限规则处理。
3. Photoshop 启动后，在 UXP Developer Tool 选择 Add Plugin，打开**当前克隆目录**下的 `PhotoshopPlugin/manifest.json`，执行 Load。UI 名称以当前 Adobe 工具为准，参考 [Adobe UDT 指南](https://developer.adobe.com/uxp/guides/how-to/udt-deep-dive/) 和 [官方加载示例](https://github.com/AdobeDocs/uxp-photoshop-plugin-samples/tree/main/hello-world-panel-js-sample)。
4. 保持 Mac 应用运行，在 Photoshop 打开 PSD Mirror 面板。插件会自动握手本机服务并同步预览；此前暂停过时点「开始实时同步」。不需要选择目录、共享路径或输入本机连接凭据。
5. 打开测试 `.psd`，保持面板打开。首次加载后默认同步；尊重使用者此前保存的暂停选择。
6. 检查插件「已同步」、Mac 底部的「Photoshop 已连接」，以及来源为「Photoshop 实时」的条目。未开启 Mac 时应等待并自动重试；Mac 重启后应自动重新握手发送。
7. 在手机选择该实时条目，或开启「跟随 Mac 当前画面」。同名的「已保存 PSD」条目不能证明实时模式已接通。
8. 在使用者指定的测试文档中做一次可撤销修改，不保存原稿，确认手机发生对应变化，再撤销并确认恢复。不要为测试覆盖原始设计稿。

源码可直接由 UDT 加载，不需要先生成 `.ccx`。`build/` 不入库，新克隆不会带有预下载的 Node、Adobe CLI、打包文件或原作者的 UXP 会话。根目录的 CLI 快捷脚本目前只支持已准备好的本机工具路径；工具缺失时应切换官方 UDT 流程，不应承诺该脚本自动安装依赖。发布到 Adobe 插件市场是另一套分发流程，本指南仅涵盖本地开发加载。

## AI 执行时的完成标准

- 使用者自己的本地签名配置生效，公开工程没有写入私人团队和凭据。
- 两个原生应用构建成功，实体手机已安装并可启动。
- 已保存 PSD 的手机预览先验证通过。
- 需要实时模式时，再验证「插件 → 本机自动连接 → Mac → iPhone」，包括未保存修改和撤销。
- 交接时说明实际运行路径、当前配对方式、重启后的重新配对和签名续期方法。
- 只有文档或构建检查通过时，明确尚未完成哪一项真机验证；不要声称全流程已完成。
- 不自动初始化用户的 Git 仓库、创建远程仓库、提交、推送或发布；这些操作等用户明确授权。

后续修改源码与定位协议问题，参考 [开发与通信协议](04-开发与通信协议.md)。
