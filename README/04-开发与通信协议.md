# 开发与通信协议

## 目录与配置

| 路径 | 作用 |
| --- | --- |
| `iOS/` | iPhone 连接界面、发现 Mac、轮询客户端、原生全屏预览 |
| `Mac/` | PSD 合成图解码、文件监听、本机插件接入、HTTP 服务和 Mac 界面 |
| `Shared/Protocol.swift` | 两端共同的画面数据结构、端口和服务常量 |
| `Shared/Pairing.swift` | 二维码连接载荷、版本检查、地址/端口/凭据验证 |
| `Mac/PairingQRCode.swift` | 本地生成二维码，包含白色静区 |
| `iOS/QRScanner.swift` | AVFoundation 后置相机扫描、权限和生命周期处理 |
| `Shared/Assets.xcassets/` | 应用图标等源码资源，应提交 |
| `PhotoshopPlugin/` | UXP manifest、HTML、JavaScript 和插件图标，应提交 |
| `Config/Signing.xcconfig` | 无私人团队的共享配置，应提交 |
| `Config/Signing.local.xcconfig.example` | 本地配置模板，应提交 |
| `Config/Signing.local.xcconfig` | 每位使用者自己的 Team 和 Bundle ID，不提交 |
| `Scripts/` | 工程生成、构建和图标生成工具源码 |
| `Tests/` | 服务端集成检查源码；程序自动生成测试 PSD |
| `PSDMirror.xcodeproj/` | 可共享的 Xcode 工程与 schemes；忽略个人状态 |
| `README/` | 使用、接入、开发和提交准备说明 |
| `build/` | 全部构建产物、测试预览、下载工具和临时日志，不提交 |

两个原生 target 不依赖 Swift Package 或 CocoaPods。插件使用 Photoshop/UXP 提供的模块，不需要 npm 构建；作者本机的 CLI 工具依赖与插件源代码是两件事。

插件面板布局位于 `PhotoshopPlugin/index.html`。当前只显示标题、清晰度选择、同步控制和动态状态，已删除实时预览、只读行为及自动连接的三行固定说明。维护界面时保留 `quality`、`toggle`、`send`、`status` 元素，供 `main.js` 绑定；固定说明的删除不影响连接或同步逻辑。修改后在 Adobe UXP Developer Tool 中重新加载插件；如分发 `.ccx`，需重新打包。仅修改插件 HTML 无需重新构建 Mac 或 iPhone 应用。

## 工程生成与构建

`Scripts/generate_project.py` 用 Python 标准库生成工程、两个共享 scheme 和两个 Info.plist。要长期修改这些生成结果，应修改生成器；签名值放到本地 xcconfig，不要写死在生成器里。

```sh
python3 Scripts/generate_project.py
zsh Scripts/build.sh mac
zsh Scripts/build.sh simulator
# 先配置本人的账号、团队、Bundle ID，再构建真机：
zsh Scripts/build.sh ios
```

iPhone scheme 为 `PSDMirror`，Mac scheme 为 `PSDMirrorMac`。Mac 构建脚本选择当前 shell 架构；Apple Silicon 已验证，其他架构需在目标环境验证。Mac 当前为本地 ad-hoc 签名且不启用 App Sandbox；不等同于已完成公证的对外分发版。

## 手机与 Mac 的协议

默认 TCP 端口为 `48765`。手机仅通过应用内扫码获取地址与凭据，不搜索附近 Mac，也没有手动输入界面。Mac 仍保留 `_psdmirror._tcp.` 服务广播，但当前扫码连接不依赖它。所有以下接口都需要 `X-Mirror-Key` 请求头，值为当次 Mac 进程生成的 8 位凭据，自动从二维码读取。错误凭据返回 401，手机提示重新扫码。

| 接口 | 返回或行为 |
| --- | --- |
| `GET /state` | JSON：`name`、`frames`、`activeID` |
| `GET /frame/<id>` | 对应预览的 JPEG 或 PNG 字节，Content-Type 随格式确定 |
| `POST /push` | 兼容带手机配对凭据的集成推送；当前 Photoshop 插件使用下述独立本机接口 |

`frames` 的每项包含：`id`、`title`、`version`、`width`、`height`、`source`，实时画板另带 `artboardName`。`title` 始终是 PSD 文件名；画板尺寸为其边界宽高。`version` 根据图像字节生成，手机按 `id + version` 判断是否需要重新下载。

当前 HTTP 服务不提供任意路径的文件下载接口。配对码不代表传输已加密；服务没有 TLS，没有互联网账号体系，应在可信局域网使用。

## 二维码连接协议

连接码格式为 `psdmirror://pair?v=1&hosts=192.168.1.10,169.254.12.34&port=48765&code=01234567`。这里的地址和凭据仅为格式示例，不代表可连接的实际服务。

`v` 为协议版本，`hosts` 是最多 8 个去重的 IPv4 接口地址，`port` 为 1–65535，`code` 必须是 8 个 ASCII 数字。Mac 优先放入常用接口地址，约每 5 秒刷新地址变化；手机连接失败时自动尝试下一个地址。二维码包含当前连接凭据，应只向获准预览的人展示，不提交实际二维码截图到仓库。

扫描器仅接受本项目版本的完整连接码，拒绝普通网址、缺失或重复字段、不支持版本、非法地址及非法端口，不会打开任意扫码网址。二维码由 Core Image 在 Mac 本机生成，识别由 AVFoundation 在手机本机完成，无第三方服务，也不上传相机画面。首次扫码需要 `NSCameraUsageDescription` 和使用者授权；离开扫描页面或应用进入后台后停止相机。

连接成功后恢复「跟随 Mac 当前画面」，不继承之前手动选图造成的停留状态。二维码失效时让使用者重新扫码，不重新引入地址或配对码输入框。

当前版本已通过 Mac、iOS 模拟器和真机构建、二维码生成/解码回读、参数校验及原有服务端集成检查；已在实体 iPhone 上确认扫描 Mac 窗口二维码后自动连接并显示 PSD。模拟器构建本身不验证相机扫描。

二维码解析与实际生成图片的识别回读可独立测试，不占用 HTTP 服务端口：

```sh
xcrun swiftc -swift-version 5 Shared/Pairing.swift Mac/PairingQRCode.swift Tests/PairingTests.swift -o build/PairingTests
build/PairingTests
```

## 插件与 Mac 的自动连接

Mac 额外监听 `127.0.0.1:48766`，只绑定 IPv4 回环地址。插件 manifest 仅声明本机域名的网络权限，不需要文件夹选择权限或任意磁盘访问。`127.0.0.1` 指运行插件的那台电脑，不是作者电脑的地址，因此克隆目录、用户名或应用包位置改变不会影响自动连接。

| 本机接口 | 作用 |
| --- | --- |
| `GET /session` | 返回 `service: psdmirror-plugin`、`version: 1` 和随机的本机会话 `key` |
| `POST /push` | 接收预览 JSON，要求握手得到的 `X-Mirror-Plugin-Key`，接收后选为当前画面 |
| `POST /artboard` | 接收单个画板：`document` 为 `/push` 的画面结构（`id` 是 PSD 文档 ID），另带 `layerID` 和 `name`；更新图片缓存，不抢占当前画面 |
| `POST /artboards` | 接收 `documentID`、`layerIDs` 和 `activeLayerID`；清理该 PSD 已删除画板、设置已缓存的当前画板，返回 `missingLayerIDs` |

插件实际请求使用 `http://localhost:48766`，manifest 的网络域名声明为 `http://localhost`。这是在 Photoshop 25.2 实际验证过的组合；该宿主对数字 IP 的网络权限匹配曾拒绝请求，不要只把请求地址替换成 `127.0.0.1` 而不重新验证。底层监听仍限制在 IPv4 回环地址。

所有请求都要求 `X-Mirror-Plugin-Client: psdmirror-uxp`，写入还需本机会话密钥。本机接口不开放浏览器 CORS，拒绝普通网页 Origin 和不带客户端标记的请求；不提供读取 PSD 列表或图像的接口。局域网端口 `48765` 不开放画板写入或本机会话接口，两套凭据相互独立。

插件约每 3 秒重新握手以检查 Mac 状态，Mac 重启后凭据变化会触发当前画面重新发送。Mac 不在线时自动重试；UI 仅显示等待或已连接，无需使用者填写路径或凭据。明确暂停仍会停止同步。

预览 JSON 结构如下，图片内容仅为占位文本：

```json
{
  "id": "123",
  "title": "Example.psd",
  "width": 1536,
  "height": 2048,
  "jpeg": "BASE64_IMAGE_BYTES"
}
```

Mac 会将插件文档 ID 转为 `live-<id>`。`jpeg` 是历史字段名，服务端也能解码其中的 PNG；当前插件实际使用 Imaging API 编码 JPEG。网络发送发生在 `executeAsModal` 之外。

画板 ID 使用 `artboard-<documentID>-<layerID>`。插件读取 `Document.artboards` 与画板矩形，分别截取各画板所在的合成图区域；普通文档仍走 `/push`。从选中图层向上查找所属画板，因此选择画板内部图层也可以触发跟随。只有选中画板变化时，插件只发送列表与当前画板，除非 Mac 缺少某张预览。每个 PSD 最多 64 个画板，Mac 共保留最多 64 张、256 MiB 的预览。

旧版 `PhotoshopBridge/`、`psdmirror-frame.json` 和持久化文件夹 token 已不再用于当前流程；仓库继续忽略可能遗留的预览数据，防止提交私人设计。升级时同时更新 Mac 应用和插件，不要仅更新一边再沿用旧版的文件夹接入步骤。

## 捕获、更新与显示

- 已保存 PSD：ImageIO 读取兼容合成图，最长边上限 8192 像素，以 PNG 传输并保留透明度，约每 0.5 秒检查文件变化。
- 插件：约每 0.6 秒检查当前文档、历史状态、尺寸、清晰度、画板列表和选中画板。图像变化时读取整张画布或各画板区域。读取和编码包在 `photoshop.core.executeAsModal` 内，网络传输在其外；释放 `imageData`，避免长期占用图像内存。
- 插件画面：sRGB JPEG，可选最长边 2048/4096/8192，透明区域按不透明预览处理。它与 PNG 模式的透明度和有损压缩行为不同。
- Mac 收到插件推送后直接更新缓存；手机轮询状态约每 0.5 秒。实际延迟还包括渲染、编码、磁盘和网络，不能承诺固定帧率。
- iPhone 使用 `UIScrollView` 和 `UIImageView`，无 WebView；同文档新画面尽量保留缩放和位置。手动选图会关闭自动跟随。
- Mac 当前最多保留 64 张/约 256 MiB 缓存，并限制并发连接及请求体大小。增加边界值时同步检查内存和解码限制。

## 验证

文档和签名配置变更至少检查工程可解析、有效 Build Settings，以及共享默认值没有依赖本地文件。功能变更按涉及范围补充实际验证。

集成测试会占用与 Mac 应用相同的端口，因此运行前退出 Mac 应用。不要在正常服务仍运行时启动测试，否则可能连接到错误的服务。

```sh
mkdir -p build
xcrun swiftc -swift-version 5 Shared/*.swift Mac/MirrorServer.swift Tests/ServerTests.swift -o build/ServerTests
build/ServerTests
```

可以额外传入使用者授权的真实 PSD 路径：

```sh
build/ServerTests '/absolute/path/to/Example.psd'
```

测试覆盖合成图解码、鉴权、画面字节传输、非 PSD 拒绝、路径访问限制、实时推送、本机插件握手、凭据与浏览器来源隔离，以及保存后版本变化；生成的样本及预览放在 `build/`。这些检查不代表插件加载或真机预览已验证，后者按接入指南单独完成。

## 修改时的注意事项

修改端口或数据字段时，同时检查 `Shared/Protocol.swift`、Mac 路由、手机客户端和插件载荷。不要因为接口返回 200 就宣称手机看到了最新画面；还要核对来源、activeID 和手机跟随状态。

不要提交真实设计图、运行日志、配对码、设备标识或个人签名产物。不要自动保存用户 PSD。涉及新增捕获能力时，以 [Adobe Imaging API](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/media/imaging) 和 [executeAsModal](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/media/executeasmodal) 为依据，并检查宿主版本兼容性。
